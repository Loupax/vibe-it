A quick reference for everything the command bar and keybindings do today. This page is rendered by scratchy's own layout engine, the same as any other page — and gets updated here as features are added.

Command bar

Press :, type a command, then Enter to run it. Tab completes the current word (a command name, or set's own vim/novim argument) — press Tab again right after to cycle through any other matches. Ctrl+v pastes from the clipboard — useful for a URL copied from somewhere else. Escape cancels without running anything.

CommandEffect
:go <url>Navigate to a URL
:refreshRe-fetch the page on screen and reload it in place (it does not add a history entry), e.g. after :set nojs/:set js or when testing a changing page
:historyBackGo back one page in history (same as h)
:historyFrontGo forward one page in history (same as l)
:set vimTurn vim-mode key handling on
:set novimTurn vim-mode key handling off (every key then passes straight through to the page)
:set motion / :set nomotionAnswer prefers-reduced-motion: no-preference / reduce (the default) to CSS and matchMedia, from the next page load; --motion starts with real motion on
:set nojs / :set jsTurn scripts off/on (and show/hide <noscript> content) from the next page load; --no-js starts with them off
:helpShow this page
:q or :quitFrom this help page, go back to whatever you were looking at; otherwise close scratchy (vim's own "close the buffer, or quit if there's nothing left to close")

Command line

scratchy [--socket <path>] [--no-js] [--state-dir <dir>] [--user-agent <string>] [file|url] opens a file, a URL, or HTML read from stdin. The other modes are headless.

OptionEffect
--socket <path>The wire daemon's Unix socket (wire --print-socket prints it). All networking goes through it: link clicks, page loads, sub-resources, and requests made by page scripts. Without it nothing is fetched
--no-jsNever run scripts; show <noscript> content
--state-dir <dir>Where localStorage is kept between runs (one file per key under <dir>/storage/<site>/<origin>/, see STASH.md). The SCRATCHY_STATE_DIR environment variable does the same (the flag wins); the default is $XDG_STATE_HOME/scratchy (~/.local/state/scratchy). A tmpfs directory keeps it until logout. Pages from file:, data: and about: keep theirs in memory; a directory that cannot be used logs one line and keeps everything in memory
--user-agent <string>Send this User-Agent for page loads, sub-resources, fetch/XHR and media requests (through wire's X-Wire-User-Agent) and report it as navigator.userAgent. Printable ASCII, at most 512 bytes, otherwise scratchy exits with an error. The SCRATCHY_USER_AGENT environment variable does the same (the flag wins). Without it wire's own User-Agent is used. An old wire cannot honour it (one warning line is logged)
--js-report [--socket <path>] [--state-dir <dir>] [--run-timers <ms>] <file>Headless: run the page's scripts and print what happened (console, errors, network, cookies). localStorage is in memory unless --state-dir is given (the environment variable and the default are not used here)
--forget-site <site or URL> [--socket <path>] [--state-dir <dir>]Headless: delete that site's stored localStorage (pages that have it open drop their later writes) and, with --socket, clear its cookies in wire. If wire cannot be reached the storage is still deleted and the log line says the cookies were not cleared (STASH.md)
--perf-report [--socket <path>] [--seconds <s>] <url|file>Headless: load the page, pump timers for --seconds (default 5) and print ONE JSON object of per-callback CPU, budget kills, forced layouts and load times (QV8-0, see PERF.md)
--seconds <s>With --perf-report: how long to keep running the page after load
--missing-api-report [--socket <path>] [--seconds <s>] <url|file>...Headless, like --perf-report plus a missing_api member: standard web APIs the page touched that scratchy lacks (get/has misses from a Proxy at the end of the DOM prototype chains), grouped V8 errors and not implemented stubs (QMAPI1)
--perf-corpus <dir>Headless: measure parse and first-run CPU of every .js in the directory plus fixed CPU loops, print JSON
--budget-ms <ms>Debug flag, any mode: the per-callback CPU budget in milliseconds (default 500); a large value lets killed work run to completion
--run-timers <ms>With --js-report: also run timers due within that many milliseconds
--wpt <checkout> [--subset FILE] [--expected FILE] [--update] [--out DIR] [-v]Headless: run the web-platform-tests reftest subset and compare with the expected results (--update rewrites them)
--wpt-th-one --socket <path> <url>Headless: load one web-platform-tests testharness.js page through wire (usually a private wire --mount), run it on a virtual clock (800x600, Ahem) and print ONE JSON line of its results, or nothing if it never reported (the runner's test child, see NOTES.md)

Cookies and networking

Page scripts can use fetch, XMLHttpRequest and sendBeacon, under a request policy: browser CORS rules, no mixed content, bad ports blocked, and a warning line (not a block) for requests to loopback, private or file: targets. Beacons are logged in detail but not sent. Cookies live in wire's memory (partitioned by top-level site, lost when it restarts; wire --no-cookies turns them off). Forms and media are placeholders only. See scratchy/NETWORKING.md in the source tree for the details.

Offline guarantee: unix sockets only

At startup scratchy installs a seccomp filter so that socket() fails for every address family except unix sockets (stderr says scratchy: network: unix sockets only (wire)). It cannot reach the internet by itself, only through wire, and this is inherited by every thread and by libmpv/ffmpeg. To verify from outside, run it with no network at all: unshare -rn scratchy --socket /path/to/wire.sock URL with wire started outside that namespace (filesystem unix sockets cross network namespaces); it must behave exactly as before. Reading file:// pages needs no wire at all.
