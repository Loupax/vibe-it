scratchy

A quick reference for everything the command bar and keybindings do today. This page is rendered by scratchy's own layout engine, the same as any other page — and gets updated here as features are added.

Modes and the status bar

The bar at the bottom of the window shows the mode (INPUT or NORMAL), the page's URL, and on the right a short message (for example a search result). While you type a command or a search, the bar shows that line instead: : or / followed by what you typed.

  • INPUT (the mode at start): keys go to the page. If the page leaves them alone, the browser defaults apply: arrows, PageUp, PageDown, Space / Shift+Space, Home and End scroll, Tab moves focus. scratchy's own keys below do nothing here.
  • Press Esc twice quickly (within 300 ms) to go to NORMAL. The first Esc reaches the page as usual, the second one never does.
  • NORMAL: keys are scratchy's, the page gets no key events. Press i to go back to INPUT. Clicking into a text field or a select also switches to INPUT. The mouse always goes to the page.
  • Going to another page does not change the mode, and a page cannot switch it by focusing a field.

Search

Press /, type a word, press Enter. It looks in the text on screen (not inside frames or text fields), as plain text, not a regular expression. It ignores case unless your query has a capital letter. Every match is highlighted and the status bar shows [i/N], or Pattern not found: .... The first match at or below the top of the screen is the current one; if there is none, it wraps and the message says search hit BOTTOM, continuing at TOP. The page scrolls to the current match: if it is not fully on screen it is centred, and if it is already fully visible nothing moves. A match inside a scrollable box scrolls that box first, then the page. n goes to the next match and N to the previous one, wrapping with a message (search hit TOP, continuing at BOTTOM going backwards); with no search yet the status bar says No previous search. The last query is kept when you go to another page, so n there searches it again. Enter in NORMAL mode clicks the current match, like a mouse click: a link is followed through the page's own click handlers, a button is pressed. If the match runs over two or more different links the status bar says Match spans N links and nothing is clicked; with no match nothing happens. Esc in the search line cancels; Esc in NORMAL mode clears the highlights. Going to another page clears them too.

Command line

In NORMAL mode press :, type a command, then Enter to run it. Escape cancels without running anything.

While you type a command name or a set argument, the rest of the best match shows dimmed after the cursor (a ghost suggestion; only when the cursor is at the end of the line, and not in the / line). Enter runs what you typed plus the ghost. Tab and Shift+Tab show the next and previous match; with a single match Tab selects it (and adds a space), so :se Tab gives :set . Right or End accept the ghost into the line. Delete hides it until your next edit, so Enter runs only what you typed. :go has no suggestion yet.

Both the : and the / line accept paste: Ctrl+v, Ctrl+Shift+v or Shift+Insert.

In a page's text field or textarea (INPUT mode), Ctrl+a selects all, Ctrl+c copies and Ctrl+x cuts the selection (not from a password field), and Ctrl+v, Ctrl+Shift+v and Shift+Insert paste. Read-only fields only copy.

Mouse and scrollbars

The page and every scrollable box have a thin scrollbar on the right. Drag the thumb to scroll, click the track to scroll one page toward the click, or hold the mouse on the track to keep paging.

What is kept between runs

Everything lives under the state directory (--state-dir, see below):

  • localStorage: one file per key under <dir>/storage/. sessionStorage is not saved: it lasts as long as the window and survives navigations. The quota is 5 Mi UTF-16 units of keys plus values per origin; change QUOTA_UNITS in src/config.rs and rebuild.
  • Pages visited: the file <dir>/history (time, URL, title), one line per visit. :go completes from it: the best match is shown dimmed as you type, Tab cycles, Enter runs it.
  • Your own completion source: in src/config.rs a row of COMPLETERS can be Source::Cmd(&["my-source"]) (see the commented example). The program runs with no shell, once per command line and argument position, with the environment SCRATCHY_LINE, SCRATCHY_WORD, SCRATCHY_ARG, SCRATCHY_URL and SCRATCHY_STATE_DIR. It prints one candidate per line; scratchy filters them by what you type. A non-zero exit or no output gives no suggestion, a missing program shows a message in the status bar, and one that runs longer than SOURCE_TIMEOUT_MS is killed.
  • Cookies: kept by wire, saved only if you start it with wire --cookie-file PATH.
  • scratchy --forget-site <site> deletes a site's localStorage and cookies (not its history).

Command line

scratchy [--socket <path>] [--no-js] [--state-dir <dir>] [--user-agent <string>] [file|url] opens a file, a URL, or HTML read from stdin. The other modes are headless.

OptionEffect
--socket <path>The wire daemon's Unix socket (wire --print-socket prints it). All networking goes through it: link clicks, page loads, sub-resources, and requests made by page scripts. Without it nothing is fetched
--no-jsNever run scripts; show <noscript> content
--state-dir <dir>Where localStorage is kept between runs (one file per key under <dir>/storage/<site>/<origin>/, see STASH.md). The SCRATCHY_STATE_DIR environment variable does the same (the flag wins); the default is $XDG_STATE_HOME/scratchy (~/.local/state/scratchy). A tmpfs directory keeps it until logout. Pages from file:, data: and about: keep theirs in memory; a directory that cannot be used logs one line and keeps everything in memory
--user-agent <string>Send this User-Agent for page loads, sub-resources, fetch/XHR and media requests (through wire's X-Wire-User-Agent) and report it as navigator.userAgent. Printable ASCII, at most 512 bytes, otherwise scratchy exits with an error. The SCRATCHY_USER_AGENT environment variable does the same (the flag wins). Without it wire's own User-Agent is used. An old wire cannot honour it (one warning line is logged)
--js-report [--socket <path>] [--state-dir <dir>] [--run-timers <ms>] <file>Headless: run the page's scripts and print what happened (console, errors, network, cookies). localStorage is in memory unless --state-dir is given (the environment variable and the default are not used here)
--forget-site <site or URL> [--socket <path>] [--state-dir <dir>]Headless: delete that site's stored localStorage (pages that have it open drop their later writes) and, with --socket, clear its cookies in wire. If wire cannot be reached the storage is still deleted and the log line says the cookies were not cleared (STASH.md)
--perf-report [--socket <path>] [--seconds <s>] <url|file>Headless: load the page, pump timers for --seconds (default 5) and print ONE JSON object of per-callback CPU, budget kills, forced layouts and load times (QV8-0, see PERF.md)
--seconds <s>With --perf-report: how long to keep running the page after load
--deterministic[=<epoch-ms>]With a report mode (--perf-report, --js-report, --missing-api-report, --wpt-th-one) as the first argument: reproducible runs. V8 --random-seed (so Math.random), a seeded crypto.getRandomValues/randomUUID, Date starting at the epoch (default 1700000000000; pass the recording's date, e.g. $(stat -c %Y DIR/index.jsonl)000; it then advances 1 ms per read) and network results delivered in request order. --missing-api-report [--socket <path>] [--seconds <s>] <url|file>...Headless, like --perf-report plus a missing_api member: standard web APIs the page touched that scratchy lacks (get/has misses from a Proxy at the end of the DOM prototype chains), grouped V8 errors and not implemented stubs (QMAPI1)
--perf-corpus <dir>Headless: measure parse and first-run CPU of every .js in the directory plus fixed CPU loops, print JSON
--budget-ms <ms>Debug flag, any mode: the per-callback CPU budget in milliseconds (default 500); a large value lets killed work run to completion
--run-timers <ms>With --js-report: also run timers due within that many milliseconds

Compares with wpt-th/expected/, writes wpt-th/areas.txt, exits 1 on a regression, unrecorded or changed file; --update records the results; --area runs one area; --dir is the wpt-th directory.

Cookies and networking

Page scripts can use fetch, XMLHttpRequest and sendBeacon, under a request policy: browser CORS rules, no mixed content, bad ports blocked, and a warning line (not a block) for requests to loopback, private or file: targets. Beacons are logged in detail but not sent. Cookies are kept by wire (partitioned by top-level site), in memory by default and lost when it restarts, or in a file with wire --cookie-file <path>; wire --no-cookies turns them off. Media are placeholders only. See scratchy/NETWORKING.md in the source tree for the details.

Offline guarantee: unix sockets only

At startup scratchy installs a seccomp filter so that socket() fails for every address family except unix sockets (stderr says scratchy: network: unix sockets only (wire)). It cannot reach the internet by itself, only through wire, and this is inherited by every thread and by libmpv/ffmpeg. To verify from outside, run it with no network at all: unshare -rn scratchy --socket /path/to/wire.sock URL with wire started outside that namespace (filesystem unix sockets cross network namespaces); it must behave exactly as before. Reading file:// pages needs no wire at all.
