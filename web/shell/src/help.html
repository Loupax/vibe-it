web

A quick reference for the keys and the command line. :q goes back to the page you were on.

Modes and the status bar

The bar at the bottom of the window shows the mode (INPUT or NORMAL), the page's URL, and on the right the last message (a load error, a command's answer). While you type a command the bar shows that line instead: : followed by what you typed.

  • INPUT: every key goes to the page, and the page and the browser do what they always do with it (text fields, Tab, arrows and PageDown scrolling, shortcuts). web's own keys below do nothing here.
  • Press Esc twice quickly (within 300 ms) to go to NORMAL. The first Esc reaches the page as usual (it may close a dialog or leave a text field); the second one never does.
  • NORMAL (the mode at start): keys are web's and the page gets no key events, except Enter. Press i to go back to INPUT. Any text field gaining focus (a click, Tab, the page focusing it itself) switches to INPUT, and so does opening a select's menu (or a context menu) with the mouse, also switches to INPUT; when that menu closes (an option picked, Esc, a click outside) web goes back to the mode you were in, unless the click focused a text field. The mouse always goes to the page.
  • Going to another page does not change the mode. Leaving a field does not switch back; press Esc twice.

Scrolling is done by giving the page a real key press (Down, PageDown, Home, ...), so the page scrolls exactly as it would for that key. The keys are the BINDINGS and SCROLL_INPUTS tables in web/shell/src/config.rs, with the timing next to them. There is no config file: edit that file and rebuild.

Command line

In NORMAL mode press :, type a command, then Enter to run it. Esc cancels. Left, Right, Home, End, Backspace, Ctrl+w (delete a word) and Ctrl+u (delete to the start) edit the line.

While you type a command name, a :go address, a :refresh or a :set argument, the rest of the best match shows dimmed after the cursor (a ghost suggestion; only when the cursor is at the end of the line). Enter runs what you typed plus the ghost. Tab and Shift+Tab show the next and previous match; with a single match Tab selects it (after a command name a space follows). Right or End accept the ghost into the line. Delete hides it until your next edit, so Enter runs only what you typed.

:go suggests from the pages you visited: sites you visit most first (you suggests YouTube's home page even if you mostly watched videos), then single pages. https://, http:// and www. are ignored when matching.

CommandEffect
:go <url>Go to a URL. Without a scheme https:// is assumed (:go example.com); /x, ./x, ../x, #x, ?x are relative to the page on screen
:refreshReload the page
:refresh hardReload the page and everything on it, bypassing the cache
:historyBackGo back one page (same as h)
:historyFrontGo forward one page (same as l)
:let @<dst> = @<src>Copy a register into another (vim's :let @+ = @%). % is the page URL as the status bar shows it (read-only), + is the system clipboard (:let @+ = @% copies the URL)
:set caret, :set nocaretTurn Chromium's caret browsing on or off (an experiment; off at every start). With it on, a text caret sits in the page and the keys that scroll move it instead: j/k and the arrows move it by line or character (the page follows), g g and G go to the start and end of its line. Ctrl+d/u and Space still scroll. /word then Esc puts the caret on the word; on a link, Enter follows it
:set caret?Show whether caret browsing is on (caret) or off (nocaret)
:forget-site [site]Delete the cookies and stored data (localStorage, IndexedDB, caches, service workers) of a site and every host under it, http and https; with no argument, of the page on screen, which is then reloaded. The result shows in the status bar (forgot ... ok). History is kept. From a terminal, web --forget-site SITE does the same, through the running web if there is one (exit status 0 ok, 1 partial, 2 refused)
:helpShow this page
:q or :quitOn this help page, go back to the page before it; otherwise close web

Ctrl+v, Ctrl+Shift+v and Shift+Insert paste the clipboard into the command line and the search line (one line: newlines and tabs become spaces).

Clipboard

web shares the clipboard with your desktop: text copied in the page (Ctrl+c) can be pasted in other programs, and text copied elsewhere pastes in the page (Ctrl+v in INPUT mode), in the command line and in the search line. Text selected in the page also becomes the desktop's primary selection (what a middle click pastes in other programs). Only text crosses over: an image or a file copied on either side does not. Middle-click paste inside the page does not work (the engine does not do it); dragging files in from the desktop does not either.

What is kept between runs

Everything lives under the state directory (--state-dir, $WEB_STATE_DIR, else ~/.local/state/web):

  • history: one line per page visited (time, URL, title). :go suggests from it. Reloads, back/forward and failed loads are not visits. scratchy's history file has the same format and can be copied over.
  • engines/cef/: the engine's profile: cookies, site storage, cache.
  • Your own completion source: in config.rs a row of COMPLETERS can be Source::Cmd(&["my-source"]). The program runs with no shell, once per command line and argument position, with WEB_LINE, WEB_WORD, WEB_ARG, WEB_URL and WEB_STATE_DIR in its environment, and prints one candidate per line.

Starting web

web [--proxy HOST:PORT] [--state-dir DIR] [URL]. Without --proxy the engine connects directly; with it every request goes through that HTTP proxy.
